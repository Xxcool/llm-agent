# 部署与运维

## 当前交付目标

当前使用 WorkBuddy 应用发布试用：免登录、访客各自配置 API Key、不同浏览器的数据隔离。不启用 OAuth，不购买服务器或域名，不选择付费算力。

免费资源可能休眠，重新访问有启动等待；该方案用于小规模试用，不承诺常驻 SLA 或无限存储。

## WorkBuddy 应用发布（当前试用）

```bash
bash scripts/sync_deploy.sh
```

默认生成 `output/workbuddy`，只含应用代码、前端产物、依赖声明、启动脚本和公开示例，不包含本机聊天、上传资料、运行配置或密钥。平台发布使用以下参数：

| 参数 | 值 |
|---|---|
| `directory` | 本地部署包的绝对路径 |
| `language` | `python` |
| `installCmd` | `pip install -r requirements.txt` |
| `startCmd` | `sh start.sh` |
| `port` | `3000` |

更新已有应用时使用其 `appId`，避免重复创建应用或更换分享链接。发布入口在 WorkBuddy 会话内；仓库脚本只生成部署包，不会自行发布。

`start.sh` 固定开启 `MULTI_TENANT=1`、`REQUIRE_USER_API_KEY=1` 和 HTTPS Cookie，使用 `static/`、`knowledge/`、`data/`，单进程监听 `3000`。不要沿用旧的 `MULTI_TENANT=0` 或共享模型 Key 参数。

**数据保存限制**：WorkBuddy 发布工具没有持久化磁盘、卷挂载或目录映射参数。现有发布记录表明同一沙箱内覆盖发布会保留运行文件，但这不是长期存储保证；沙箱被回收、重建或平台发生故障后，聊天、知识、配置和 Cookie 签名密钥可能丢失。未接独立持久存储前按试用环境使用。将快照写入同一临时沙箱不能解决这一限制。

## 魔搭创空间（备选试用）

前置条件：注册魔搭账号，绑定阿里云账号并完成实名认证。创建 Docker 创空间，选择免费 CPU。可选择「仅公开体验」隐藏空间代码；应用本身允许访客直接使用。

本地使用 Python 3.12+ 和 Node.js 22.12+（`.nvmrc` 推荐 22.22.2）：

```bash
npm --prefix frontend ci
npm --prefix frontend run build
python3 scripts/prepare_deploy.py output/modelscope --target modelscope
```

部署包根目录为 `output/modelscope`。网页中选择文件，一次上传 `Dockerfile`、`README.md`、`requirements.lock`、`application.tar.gz` 四个文件，无需手动创建子目录。包内 Dockerfile 来自 `Dockerfile.modelscope`；压缩包仅含代码、前端产物、锁定依赖及公开示例，不带本地数据、个人资料、环境变量文件或密钥。

容器固定监听 `0.0.0.0:7860`，单进程运行。以下设置已写入专用 Dockerfile：

| 变量 | 值与作用 |
|---|---|
| `MULTI_TENANT` | `1`，浏览器独立工作区；公开部署禁止关闭 |
| `REQUIRE_USER_API_KEY` | `1`，用户未填写自己的 Key 时不调用模型 |
| `CLIENT_COOKIE_SECURE` | `true`，工作区 Cookie 仅通过 HTTPS 发送 |
| `EMBED_BACKEND` | `hash`，不依赖下载语义模型；检索有字面兜底 |
| `DATA_DIR` | `/tmp/llm-agent-data`，SQLite 和实时文件位于本地文件系统 |
| `SNAPSHOT_DIR` | `/mnt/workspace/llm-agent-snapshots`，只存完整快照 |

不要给公开容器设置共享 `LLM_API_KEY`。多租户代码也不会把环境变量中的平台 Key 分配给访客。

分享部署成功后的独立应用 HTTPS 链接。创空间内嵌预览可能受到第三方 Cookie 限制，页面会提示在独立窗口使用。

## 数据与恢复

- 身份是签名、HttpOnly Cookie，不是账号。不同 Cookie 的会话、消息、任务、知识库、代码文件和配置分别存储；同一浏览器多人共用仍会共享数据。
- 清除 Cookie、无痕窗口或换设备会进入新工作区。没有跨设备找回功能；复制 Cookie 可冒充该工作区，请勿分享浏览器网站数据。
- API Key 使用 Fernet 加密。自动生成的加密密钥和 Cookie 签名密钥位于数据根目录，随快照保存；维护者仍具有服务器管理权限。
- 魔搭持久目录可能由对象存储挂载，不在其中直接打开 SQLite。快照使用 SQLite backup API，压缩包复制完成后才写入带 SHA-256 的清单。
- API 写入完成与 SSE 结束后触发快照；失败由 30 秒后台重试。存活探针的 `storage_ok=false` 表示备份失败。强制终止、平台故障或未完成备份时，仍可能丢失最近写入。
- 冷启动仅在本地数据目录为空时恢复，验证压缩包哈希和 SQLite 完整性；最新快照无效时回退上一完整版本。所有快照损坏则拒绝启动，不生成假空工作区。
- 保留最近三个完整快照。离线备份时将压缩包与对应 JSON 清单一起下载。重建空间后将二者恢复到原 `SNAPSHOT_DIR`，保持加密密钥和 Cookie 签名密钥；不要把快照上传到公开仓库。
- `GET /api/health` 无副作用、不调用模型；模型可用性另用当前工作区的 `/api/status` 查看。

## 发布验收

1. 两个不同浏览器分别录入测试对话和知识，确认列表、链接、文件、任务及 Key 均不互通。
2. 每个浏览器独立配置模型 Key；未配 Key 的浏览器应收到配置提示。
3. 做一次方案确认、文档交付、代码 diff 审批和知识归档。
4. 重启服务，再用原浏览器确认历史、知识和个人配置仍在。
5. 检查 `storage_ok` 与运行日志；只用明确的测试数据，不上传真实敏感资料作验收。

## 本机 Docker 与手动部署

根 `Dockerfile`、`docker-compose.yml` 用于本机或自有主机，默认端口 8000，Compose 挂载 `backend/data`、`backend/knowledge`。本地可靠磁盘可以直接运行 SQLite，无需开启快照。

```bash
docker compose up -d --build
```

Docker/CI 使用 `backend/requirements.lock`。Node 22，Python 3.12。公网手动部署须开启 HTTPS、`CLIENT_COOKIE_SECURE=true`，并保持 `MULTI_TENANT=1`。

## 安全部署包

打包脚本只复制 `knowledge/samples`，不从整个知识目录同步资料。只允许空目录或脚本先前生成的部署包；目标含运行数据或其他文件时拒绝覆盖，数据不会被删除。

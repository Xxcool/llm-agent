# 部署与发布

## 一份代码，两种形态

开发与部署跑的是同一份代码，差异全部由环境变量控制（定义见 `backend/app/config.py`）：

| 变量 | 开发（默认） | 部署 |
|---|---|---|
| `MULTI_TENANT` | `1` 多租户，每个浏览器独立工作区（Cookie 签名隔离） | `0` 单租户，所有请求共用一套数据 |
| `STATIC_DIR` | `frontend/dist` | `static` |
| `EMBED_BACKEND` | `auto`（优先 fastembed 语义模型） | `hash`（沙箱下不了模型，直接走降级向量 + 字面兜底） |
| `KNOWLEDGE_DIR` | `backend/knowledge` | `knowledge` |

因此**不需要维护第二份裁剪过的后端代码**。

## 同步到部署目录

```bash
bash scripts/sync_deploy.sh              # 默认同步到与仓库同级的 llm-agent-live
bash scripts/sync_deploy.sh /path/to/dir # 或指定目录
```

脚本会：构建前端 → 拷 `backend/app` → 拷 `frontend/dist` → 同步 `requirements.txt` 与示例知识库
→ 自检（无 `.pyc` / 数据库 / `.env`、`index.html` 引用的资源齐全、`app` 与主仓库一致）。

只做本地同步，不触发生效。

## 发布

发布走 WorkBuddy 的应用发布能力（会话内由助理调用，终端没有对应命令）。
固定参数：

| 参数 | 值 |
|---|---|
| directory | 部署目录（如 `~/WorkBuddy/llm-agent-live`） |
| language | `python` |
| installCmd | `pip install -r requirements.txt` |
| startCmd | `EMBED_BACKEND=hash MULTI_TENANT=0 STATIC_DIR=static KNOWLEDGE_DIR=knowledge uvicorn app.main:app --host 0.0.0.0 --port 3000` |
| port | `3000` |
| appName | `企业知识智能体` |
| domainPrefix | `llm-agent` |

发布是覆盖式的：目录不变则应用与分享链接都不变。

## 三个已知坑

1. **不要用 `requirements.lock`** —— 那是本地 Python 3.13 freeze 的结果，沙箱装不上；只装 `requirements.txt`。
2. **`startCmd` 里不要写 `$PORT`** —— 沙箱不展开变量，会报 `--port requires an argument`；端口写死 `3000`。
3. **前端产物必须在部署目录的 `static/` 下**，不能放 `dist/`。
